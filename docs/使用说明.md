# WinLaunch 使用说明（v1.0）

Windows 10/11 上的 macOS 式「启动台 + 程序坞」。免安装、免管理员、不联网。

---

## 1. 启动

从 [Releases](https://github.com/yaqisun1993-pixel/WinLaunch/releases) 下载安装包安装，或解压绿色版后双击 `WinLaunch.exe`。

从源码构建：

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

> `build.ps1` 编译后默认部署到 `%LOCALAPPDATA%\Programs\WinLaunch`（`-DeployTo` 改目录，`-NoDeploy` 只编译不部署），运行该目录下的 `WinLaunch.exe` 即可。
> `dist\run.cmd` 只是兼容入口。**建议从普通用户目录运行**，不要从只读或受限目录直接启动，否则程序可能写不了 `%APPDATA%`，托盘气泡会提示「运行环境受限」，从本程序启动的软件也可能报权限错误。

启动后：

- 屏幕底部中央出现半透明**程序坞**；
- 托盘区出现 WinLaunch 图标（蓝色渐变圆角方块 + 九宫格）。

首次启动会自动扫描开始菜单与 UWP 应用（约 3 秒），并预置 5 个常用应用到程序坞。

**退出**：托盘图标右键 → 「退出 WinLaunch」。

## 2. 快捷键

| 操作 | 快捷键 |
|---|---|
| 打开 / 关闭启动台 | `Ctrl + Alt + L` |
| 显示 / 隐藏程序坞 | `Ctrl + Alt + D` |
| 启动台内搜索 | 直接输入 |
| 移动焦点 | `←` `→` `↑` `↓` |
| 启动焦点应用 | `Enter` |
| 关闭启动台 / 清空搜索 | `Esc` |
| 启动台翻页 | `PageUp` / `PageDown` / 滚轮 |

> 说明：`Ctrl+Alt+Space` 会被 Windows 提前吞掉（注册成功但收不到消息），因此改用 `Ctrl+Alt+L`。
> 热键可在 `config.json` 的 `Hotkeys` 字段修改，格式如 `"Ctrl+Alt+L"`。

## 3. 程序坞（Dock）

| 想做什么 | 怎么做 |
|---|---|
| 启动 / 切窗 / 最小化 | 未运行：单击启动；被其他应用盖住或被最小化：单击切到前台；**它的窗口已经在最上层（即使当前焦点在桌面/任务栏上）：单击直接最小化**（多窗口应用整组最小化）；右键「打开」始终只切到前台，不切换最小化 |
| 辨认应用 | 图标即应用本身，鼠标悬停会放大（不显示浮动名称，避免干扰） |
| 调整顺序 | 按住图标左右拖动，其他图标会让位，松手即保存 |
| 加入程序坞 | 从启动台拖图标到程序坞；或从资源管理器拖 `.lnk` / `.exe` / `.url` / 文件夹进来 |
| 移出程序坞 | 按住图标向上拖出栏外约 90px 松手；或右键 →「从 Dock 移除」 |
| 运行中应用 | 未固定在 Dock 的应用打开后会自动出现在 Dock 末尾，与固定应用用一条竖线隔开；关闭后自动消失 |
| 右键菜单 | 深色圆角菜单：打开 / 在资源管理器中显示 / 退出应用 / 强制退出；运行中临时应用还有「固定在 Dock」，已固定应用还有「从 Dock 移除」 |
| 打开启动台 | 点击程序坞最左端的九宫格按钮 |

程序坞中图标下方的小圆点表示该应用正在运行。

## 4. 启动台（Launchpad）

- 全屏铺开本机所有应用图标，背景是当前屏幕的实时虚化。
- **分页**：9 列 × 5 行（随分辨率自适应），底部圆点指示页码，滚轮或方向键翻页。
- **搜索**：顶部输入框按名称过滤（输入即筛），也支持拼音/英文首字母（如 `wx` → 微信、`vsc` → Visual Studio Code）。
- **排序**：第三方应用在前，Windows 自带应用（设置、计算器、照片、附件里的经典工具等）整组排在最后，组内按中文拼音。
- **常用行**：搜索框下方自动显示最近最常用的 8 个应用（见下）。
- **点击图标**：启动应用并自动关闭启动台。
- **拖到程序坞**：按住图标往下拖，落到程序坞上松手即钉住。
- **关闭**：`Esc`、点击空白处、或再按一次 `Ctrl + Alt + L`。

### 常用（自动记录）

搜索框下方会有一张「常用」卡片（圆角半透明，和程序坞同一套视觉语言），最多 8 个图标，点一下直接打开。

- **怎么来的**：每次从启动台或程序坞打开应用都会记一次；切回已运行的窗口也算一次。
- **排序规则**：`打开次数 × 时间衰减`（半衰期 21 天），所以老习惯会慢慢退出，新习惯会顶上来。
- **数据位置**：`data\usage.json`（便携模式）或 `%APPDATA%\WinLaunch\usage.json`，是明文 JSON。
- **清空**：退出程序 → 删除 `usage.json` → 重启。
- **搜索时**：这一行会自动隐藏，清空搜索后恢复；没有历史记录时整行收起，不占空白。

## 5. 托盘菜单

| 菜单项 | 说明 |
|---|---|
| 打开启动台 | 同 `Ctrl+Alt+L` |
| 显示 / 隐藏程序坞 | 同 `Ctrl+Alt+D` |
| 悬停放大 | 开关图标放大效果 |
| 自动隐藏程序坞 | 鼠标离开后自动下滑，触底边再滑出 |
| 开机自动启动 | 写入 `HKCU\...\CurrentVersion\Run`，不需要管理员 |
| 重新扫描应用 | 新装了软件后手动刷新清单；**同时清空图标缓存并重新提取**（图标不对也点它） |
| 打开配置目录 | 直接打开数据目录 |
| 退出 WinLaunch | 完全退出 |

## 6. 数据与配置

数据目录按以下顺序自动选择：

1. `%APPDATA%\WinLaunch\`（默认）
2. 若该目录不可写（受限环境），自动回退到 **便携模式**：`WinLaunch.exe 同级的 data\`

```
WinLaunch/
  config.json        配置：Dock 顺序、设置、热键
  config.bak.json    上一次成功写入的备份（损坏时自动回滚）
  cache/icons/*.png  图标缓存，可随时删除，会自动重建
  logs/*.log         运行日志（追加写入，可随时删除）
```

> 正常模式下配置/日志在 `%APPDATA%\WinLaunch`，图标缓存在 `%LOCALAPPDATA%\WinLaunch\cache\icons`；便携模式下都在 exe 同级的 `data\`。

**重置到初始状态**：退出程序 → 删除 `config.json` → 重新启动（会重新预置程序坞）。

**常见可调项**（编辑 `config.json` 后重启生效）：

| 字段 | 说明 |
|---|---|
| `Dock.Magnification` | 是否启用悬停放大 |
| `Dock.AutoHide` | 是否自动隐藏 |
| `Hotkeys.ToggleLaunchpad` / `ToggleDock` | 全局热键 |

> `Dock.IconSize`、`Dock.Alignment`、`Launchpad.Columns/Rows`、`SortMode` 等字段为后续版本预留，v1.0 尚未接线（图标固定 44，网格按屏幕自适应）。

## 7. 已知限制（v1.0）

| 项 | 说明 |
|---|---|
| 多显示器 | 目前只铺主屏；后续版本按设计文档补"跟随光标所在屏" |
| DPI | 采用系统级 DPI 感知，150% 缩放下清晰；混合 DPI 双屏拖动尚未做逐屏适配 |
| UWP 图标 | 部分商店应用只有"纯色磁贴"图标（这是应用自身资源如此），非提取失败 |
| 拖拽 | 已实现 Dock 内排序、启动台→Dock、外部文件拖入；拖拽手感仅人工验证过一部分 |
| 全局热键 | 若被其他软件占用，日志里会记 `[WARN]`，可改 `config.json` |
| 提权应用 | 以普通权限运行，需要管理员的应用会由系统弹 UAC |

## 8. 故障排查

| 现象 | 处理 |
|---|---|
| 双击没反应 / 没有 Dock | 看数据目录下的 `logs\winlaunch-*.log`；确认没有占用同名热键的软件 |
| 点击图标、悬停、热键全都无反应 | v1.0 早期构建的已知问题（进程枚举阻塞 UI 线程），已修复在最新构建中；重新运行最新构建即可 |
| 想诊断某个应用的识别情况 | 运行 `WinLaunch.exe --activate-test "<快捷方式路径或AUMID>"`，日志会记录 `aumid/pids/hits` 与是否激活成功，便于定位 |
| 点已在运行的图标却又开了一个 | 看日志里的 `[ACTIVATE-MISS]`（带 `pids/pathHits/nameHits` 计数）。托盘类应用的隐藏窗口现在会走 `[ACTIVATE-HIDDEN]` 被唤醒；若仍匹配不到，才会退化为"再启动一次" |
| 连点图标会打开多个同一应用 | 最新构建已加启动去重：从启动到窗口出现的 15 秒内，重复点击只允许启动一次（日志会写 `[LAUNCH-SKIP]`）。WinLaunch 自身是单实例，不会开多个进程或复制窗口 |
| 想验证启动去重 | 先退出 WinLaunch，再运行 `WinLaunch.exe --launch-test "<exe路径>"`：它会在 0.4 秒内连点两次，日志应出现一次 `[LAUNCH]` + 一次 `[LAUNCH-SKIP]`；`--activate-test` 同理需要先退出 WinLaunch |
| 最小化后点 Dock 图标没反应 | 最新构建已修复：先排除桌面歌词/迷你播放器等工具窗，再优先唤醒被隐藏的主窗口（如网易云音乐的 `OrpheusBrowserHost`）。仍无反应时看日志 `[ACTIVATE]` 的 `hwnd/via/visible/fg` |
| Clash Verge 这类应用点关闭按钮关不掉 | 它们的「关闭」是**最小化到托盘**，进程还在，所以 Dock 仍会显示；窗口隐藏时 Dock 图标会消失。要彻底退出：Clash 托盘右键 →「退出」，或 Dock 右键 →「退出应用」/「强制退出」（强制退出会结束 GUI 进程，但 Clash 的代理核心/服务可能仍在，需用 Clash 自己的退出） |
| 图标空白 / 显示成通用"空白文档" | 托盘右键 →「重新扫描应用」会同时重建图标缓存；也可以手动删除缓存目录（`%LOCALAPPDATA%\WinLaunch\cache\icons` 或便携模式下的 `data\cache\icons`）后重启。新版会用目录里的 `icons.version` 自动清理旧缓存（图标管线升级时无需手动删）；个别自带资源不规范的工具类软件可能被缓存成通用文档图标 |
| 配置损坏 | 程序会自动回滚 `config.bak.json`；也可直接删除 `config.json` 重置 |
| 启动台打不开 | 检查 `Ctrl+Alt+L` 是否被占用；或改配置里的 `Hotkeys.ToggleLaunchpad` |
| 程序坞被全屏应用挡住 | 全屏时 Dock 会主动让位，退出全屏后自动回来 |
| 托盘气泡提示「运行环境受限」 | 说明本实例无法写 `%APPDATA%`，已自动使用便携模式。请把程序放到**普通可写目录**（例如用户目录下自己建的文件夹）再运行，不要从只读或受限目录直接启动 |
| 点图标被系统拒绝 / 一直有弹框 | 旧版本在受限环境用模态对话框提示，会卡住整个 UI；最新版本已改为托盘气泡，不再阻塞。若仍出现，退出程序后从普通目录重新运行 |
| 打开某些软件报"注册表不可写"等权限错误 | 检查日志首行"数据目录"：如果显示**便携模式**，说明 WinLaunch 跑在受限环境里，它启动的子程序会继承限制。从普通目录以正常权限运行即可 |

## 9. 从源码构建

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
# 自定义部署目录 / 不部署：
powershell -ExecutionPolicy Bypass -File build.ps1 -DeployTo 'D:\Apps\WinLaunch'
powershell -ExecutionPolicy Bypass -File build.ps1 -NoDeploy
```

- 目标框架：.NET Framework 4.8（Windows 10 内置，**无需安装 .NET SDK**）
- 编译器：系统自带 `csc.exe`（C# 5 语法）
- 部署产物：`%LOCALAPPDATA%\Programs\WinLaunch\WinLaunch.exe`（约 131 KB，单文件）；`dist\run.cmd` 仅作兼容入口，不放 exe
- 源码：`src\*.cs`，UI 全部用代码构建（无 XAML 编译依赖）
